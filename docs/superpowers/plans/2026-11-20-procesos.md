# Procesos (ciclo reproductivo): plan de construcción

> **Para quien lo ejecute:** se sigue tarea por tarea con TDD (`superpowers:test-driven-development`). Los pasos usan casillas (`- [ ]`). **Sin commits**: Diego los pide aparte.

**Objetivo:** registrar el ciclo reproductivo (servicio → diagnóstico → parición → destete) como un **proceso**, con su ficha, su pestaña en Registro y su embudo calculado.

**Arquitectura:** `Proceso` + `ProcesoLote` son tablas nuevas. Cada etapa deja un evento **ancla** en `evento_registro` (`proceso_id`, `etapa`), y sus movimientos cuelgan del ancla (`movimiento.proceso_id`, `registro_id`). Los movimientos de una carga se agrupan en un `EventoMovimiento` de tipo `PROCESO`, así se revierten juntos. La plantilla de etapas y las cuentas son puras.

**Stack:** Express 5, Prisma 7.10.1 + PostgreSQL 18, zod 4, React 19, Vitest + supertest.

**Diseño:** `docs/superpowers/specs/2026-11-20-procesos-design.md`. Se lee junto con este plan: los § de abajo son de ese documento.

## Reglas de todo el plan

- Textos en voseo; comentarios en español; errores con `badRequest` / `conflict` / `notFound` (`src/errors.js`); auditoría con `registrar(req, …)`.
- Migración con `npx prisma migrate dev --name procesos` y `npm run db:generate`. **Nunca** `migrate reset`, `db push --force-reset` ni `--accept-data-loss`. Si cambia el seed: `npm run db:seed` en la base local.
- Tests contra PostgreSQL real; solo datos ficticios (estancia "EJ", lotes "Lote V"…).
- Suites completas una sola vez al final de cada paso grande y nunca dos a la vez: `C:\dev\sapsa-app\server` → `npm test`; `C:\dev\sapsa-app\client` → `npx vitest run` y `npx vite build`.
- Paradas para el OK de Diego: después de las tareas 2, 3, 4, 5, 6 y 7. Al parar, actualizar `CLAUDE.md`.
- Valores fijados por el diseño:
  - `GESTACION_DIAS` = 283, `DIAGNOSTICO_DESDE_DIAS` = 45 y `DESTETE_EDAD_DIAS` = 180;
  - aviso de parición temprana antes de inicio + 260 días;
  - campaña de julio a junio ("2026-27");
  - porcentajes sobre las servidas.

## Lo que hay que vigilar (no lo cubre ninguna tarea sola)

1. **Un lote del proceso que se toca con el "+" normal** (se suma a otro, sale entero, se va a otra estancia). La ficha del proceso no se tiene que romper: muestra el lote cerrado y "salió del proceso". Test en la tarea 7.
2. **Dos cargas de la misma etapa al mismo tiempo.** La segunda tiene que dar el error de "ya tiene", no un 500. Test en la tarea 2 (índice único + `FOR UPDATE`).
3. **Anular una carga vieja cuando después hubo otra** (anular el diagnóstico después de una parición). Se rechaza con el mensaje de "hubo otros cambios en P12", sin dejar nada a medias. Test en la tarea 6.
4. **Números en texto con coma** ("6", "6,0", ""). Se aceptan como en los eventos; vacío = 0 en la parición. Test en la tarea 5.
5. **Un proceso de una estancia que el usuario no tiene.** Contesta 404 en la ficha, en las etapas y en la lista (no aparece). Test en la tarea 2.
